# Zero-width-character
You can change the text to zero-width spaces or reverse it
InvisiText

> 把秘密藏进看不见的地方。所有处理均在浏览器本地完成，不上传任何数据。

一个纯前端、单文件、零依赖的隐写工具。把秘密信息编码为零宽字符（U+200B / U+200C），嵌入到一段普通的伪装文字中——肉眼完全不可见，复制粘贴也不会丢失。别人看到的只是一句平常的话，只有用解码功能才能读出真正隐藏的内容。

---

## ✨ 功能特性

- **🔒 加密隐写** — 把秘密藏进一段普通文字里，看不出任何异常
- **🔓 解密读取** — 从收到的文字中自动提取隐藏数据
- **🔐 可选密码加密** — 使用 PBKDF2 + AES-256-GCM，密码错误无法解密
- **🔗 分享链接** — 一键生成 URL（可选 deflate 压缩 + Base64URL），对方打开即自动解密
- **👁 可视化调试** — 一键显示所有隐藏字符（`[0]` / `[1]` 标记）
- **📱 响应式 UI** — 向导式分步操作，深色/浅色主题，移动端友好
- **🛡 完整性校验** — 内置 CRC32 校验，检测数据是否被平台篡改
- **📦 单文件部署** — 只有一个 `index.html`，双击即可用
- **🌐 完全离线** — 没有任何网络请求，无第三方 SDK，无追踪

## 🚀 快速开始

### 方式一：直接打开

下载 `index.html`，用浏览器打开即可。

### 方式二：本地服务器（推荐，因为分享链接 / 剪贴板 API 需要安全上下文）

```bash
# Python 3
python -m http.server 8000

npx serve .
```

然后访问 <http://localhost:8000>。

把 `index.html` 上传到任意静态托管服务即可（GitHub Pages / Cloudflare Pages / Vercel / Netlify…）。
建议启用 HTTPS，以支持剪贴板 API 和 Web Crypto。

## 📖 使用说明

### 加密（藏入密文）

1. 首页选择 **「🔒 加密 · 藏入密文」**
2. 填写 **伪装文字**（别人能看到的表面内容），例如：
   > 今天天气真好，我们一起去公园散步吧。
3. 填写 **秘密内容**，例如：
   > 周五下午三点，老地方见。
4. （可选）设置 **密码**。留空则仅隐写、不加密。
5. 点击 **「生成隐写文本」**，得到看起来与伪装文字一模一样的输出。
6. 两种发送方式：
   - **复制文本** — 直接发给对方（注意：需保留完整文本，勿手动编辑）
   - **复制分享链接** — 对方打开链接即可自动解密

### 解密（读取密文）

1. 首页选择 **「🔓 解密 · 读取密文」**
2. 粘贴收到的隐写文本
3. 如果发送方设置了密码，在密码框中输入
4. 点击 **「解码」**，即可看到秘密内容

## 🔬 技术原理

### 零宽字符映射

使用两种不可见字符表示二进制位：

| 字符 | Unicode | 含义 |
|------|---------|------|
| 零宽空格 | `U+200B` | 比特 `0` |
| 零宽非连接符 | `U+200C` | 比特 `1` |

每个字节编码为 8 个零宽字符（MSB 优先）。

### 数据包格式

```
┌──────────┬─────────┬────────┬──────────┬───────────────┬────────┐
│  MAGIC   │ VERSION │ FLAGS  │  LENGTH  │    PAYLOAD    │ CRC32  │
│ 4 bytes  │ 1 byte  │ 1 byte │ 2 bytes  │   N bytes     │ 4 bytes│
│ "IVTX"   │  0x01   │ bit0=加密│ 大端序   │  密文或明文    │ 大端序 │
└──────────┴─────────┴────────┴──────────┴───────────────┴────────┘
```

- `MAGIC`：`0x49 0x56 0x54 0x58`（ASCII `"IVTX"`）
- `FLAGS`：`0x01` 表示已加密
- `LENGTH`：载荷字节数，最大 `65535`（约 64 KB）
- `CRC32`：对 `MAGIC..PAYLOAD` 计算，用于完整性校验

### 加密方案

当设置了密码时：

1. 随机生成 16 字节 Salt 和 12 字节 IV
2. `PBKDF2-SHA256`（200,000 次迭代）派生 256 位密钥
3. `AES-256-GCM` 加密明文，得到密文 + 认证标签
4. 载荷结构：`Salt(16) || IV(12) || Ciphertext`

### 嵌入与提取

- **嵌入**：零宽字符序列插入到伪装文字的**第一个字符之后**，其余原样保留
- **提取**：扫描全部零宽字符，按连续段切分（忽略长度 < 16 的短段），按长度降序尝试解析
- **兼容多段**：即使文本中存在其它无关零宽字符，也能正确定位有效载荷

### 分享链接

- 将数据包先尝试 `deflate-raw` 压缩（`CompressionStream`），压缩有效则加标记 `0x01`，否则用 `0x00`
- 结果用 Base64URL 编码后放入 `?d=` 参数
- 若设置了密码，会一并写入 `?password=`（**注意：这会明文暴露密码，仅适合可信渠道**）
- 打开链接后，脚本会立即解密，并调用 `history.replaceState` 清理 URL

## ⚠️ 注意事项

### 安全性说明

- **隐写 ≠ 加密**。零宽字符隐写只是为了「不引起注意」，如果对方使用十六进制编辑器或查看字符编码，很容易发现隐藏数据。**涉及敏感内容请务必设置密码。**
- **分享链接中的密码是明文的**。分享链接的 `password` 参数未做额外保护，请勿在公开渠道使用。
- **PBKDF2 迭代次数为 200,000**，在现代设备上解锁约需 0.2–1 秒，属正常现象。
- 本工具**不提供任何防抵赖 / 前向保密**，请自行评估使用场景。

### 平台兼容性

零宽字符可能被某些平台**过滤、转义或规范化**：

| 平台 | 情况 |
|------|------|
| 微信 / QQ | 部分版本会过滤零宽字符，可能丢失 |
| 微博 / 知乎 | 通常保留，但编辑器中不可见 |
| 纯文本邮件 | 一般保留 |
| Markdown 渲染器 | 通常保留 |
| 富文本编辑器 | 可能被规范化（如 `U+200B` → 空） |

**建议**：发送后先让接收方确认是否能解码成功，或直接使用分享链接。

### 字符膨胀比

每个明文字节会变成 **8 个零宽字符**。一段 100 字的伪装文字大约能安全承载几十字节的秘密。伪装文字过短时，界面会提示膨胀比过高。

### 浏览器要求

| 功能 | 要求 |
|------|------|
| 基础隐写 / 解密 | 所有现代浏览器 |
| 密码加密 | 需要 `Web Crypto API`（HTTPS 或 localhost） |
| 分享链接压缩 | 需要 `CompressionStream`（Chrome 80+ / Edge 80+ / Safari 16.4+ / Firefox 113+） |
| 复制到剪贴板 | 优先使用 `navigator.clipboard`，否则回退到 `execCommand` |
